datafev_flex Service Flowchart

Stage-1 + Stage-2 (Strict / Best-Effort) + Tracking Analytics

ENTRYPOINTS & RUNTIME MODES

Local (No Docker)

  • - `python run_local_workflow.py`
  • - Stage-1 + Stage-2 single-process run
  • - Manual tuning of solver/profile/exports

HTTP Service (FastAPI)

  • - `POST /v1/flex-potential-estimation`
  • - `POST /v1/flex-aware-smart-charge-scheduling`
  • - `GET /healthz`, `GET /readyz`

STAGE-1 FLEX POTENTIAL ESTIMATION

Input + Parsing

  • - `Planning`, `Fleet`, `Clusters` sheets
  • - Horizon: `planning_start/end`, `time_step_minutes`
  • - Build `EVFleet` + `MultiClusterSystem`

MILP Outputs

  • - G2V envelope (downward capability)
  • - V2G envelope (upward capability)
  • - Per-cluster capability time-series

STAGE-1 CACHE + JOB WORKSPACE

Cache Contract

  • - Return `stage1_id` to client
  • - TTL cache keeps Stage-1 artifacts
  • - After successful Stage-2: cache entry removed

Artifacts

  • - `outputs/jobs/<stage1_id>/flex_potential_estimation`
  • - Capability files + plots
  • - Request-scoped result isolation

EXTERNAL SERVICE

Service Communication

  • - Send Stage-1 G2V/V2G capabilities
  • - Share `stage1_id` for request traceability
  • - Receive commands for Stage-2 scheduling

Command Payloads

  • - `absolute_setpoint` (`p_set_kw`)
  • - `flex_band` (`p_min_kw`, `p_max_kw`)
  • - JSON inline or XLSX upload formats

STAGE-2 COMMAND INTAKE + VALIDATION GATE

Command Types

  • - `absolute_setpoint` (`p_set_kw`)
  • - `flex_band` (`p_min_kw`, `p_max_kw`)
  • - JSON inline or XLSX upload

Tracking Modes

  • - `strict` (default): envelope enforced
  • - `best_effort`: envelope soften + minimize mismatch
  • - `match_tolerance_kw` for `is_met` decision

Validation Outcomes

  • - `TIMESTEP_MISMATCH`, `UNKNOWN_CLUSTER`
  • - `OUT_OF_ENVELOPE`, `INVALID_BAND_RANGE`
  • - `INFEASIBLE_MILP`, `BEST_EFFORT_DEVIATION`

STAGE-2 MILP SCHEDULER + TRACKING ANALYTICS

Hard Constraints

  • - EV arrival/departure windows
  • - SoC dynamics + min/max SoC
  • - Target SoC policy (`use_target_soc`, `exact_target_soc`)
  • - Charge/discharge power limits

These remain hard in both `strict` and `best_effort`.

Tracking KPIs per Timestamp

  • - `datetime`
  • - requested (`p_set` or `p_min/p_max`)
  • - `delivered_p_kw`
  • - error (`abs_error_kw` or `band_violation_kw`)
  • - `is_met` (true/false)

Summary: matched_steps, total_steps, match_ratio, mean/max error.

OUTPUTS, EXPORTS, AND OPERATIONS

Primary Exports

  • - Stage-1 capability CSV/XLSX/Parquet
  • - Stage-2 scheduling XLSX/CSV
  • - Stage-2 tracking report per cluster

Artifacts by Job

  • - `outputs/jobs/<id>/flex_potential_estimation`
  • - `outputs/jobs/<id>/flex_aware_smart_charge_scheduling`
  • - Deterministic acceptance fixtures available

Service Ready: strict + best_effort scheduling with full traceability
